# Series identity, source matching, naming

- **The image-cache rebuild is asymmetric on purpose** (`ImageCacheRebuildService`, `POST system/image-cache/rebuild`): reader thumbnails and source-preview samples are only *deleted* (any request regenerates them), while posters are *re-downloaded*, because nothing regenerates a poster and `Series` stores only `CoverPath`, so each costs a provider lookup. The default pass targets only covers that are missing or fail `Image.Identify`; the forced one is behind a confirm. The single-flight claim is taken inside the service, not the endpoint, so a trigger that never reaches the job can't leave the status stuck on "running".
- **`Series.LockedFields` marks metadata a user set by hand** (title, synopsis, status, chapter and volume totals, genres, cover; flags, persisted, append only). `SeriesMetadataRefreshService.RefreshAsync`, `RefreshCoverAsync` and the image-cache rebuild skip a locked field, and **any new writer of a lockable field must check `Series.IsLocked` too**, or a refresh silently undoes the edit. Only `SeriesMetadataController` sets or clears a lock (`MediaCoverController.Upload` for the cover); a reset unlocks and refreshes with the field in `restore`, so an empty provider value replaces the user's. A title edit on a series with no provider ids moves its `SeriesIdentity` key, so it re-keys that series' `StatsEvents` in the same transaction (`SeriesIdentityService.RekeyAsync`). Title, status and total changes are logged to `SeriesMetadataChanges`; `SeriesStatusChanged` is raised after the save, not before.
- **`SeriesRequest` needs no permission to create**: it's the 403 fallback for users without `AddSeries`/`DownloadChapters`. Resolving is admin-only; a requester lists their own rows in any status (resolved ones carry `ResolutionNote`) and can withdraw only **pending** ones. The display snapshot (title/cover/year) is resolved server-side, never from the request body. Approval goes through `SeriesCreationService` (same code as `SeriesController.Add`), with `deferSourceMatching = false` since a chapter range gets queued right after.
- **MangaBaka has no MangaDex IDs**: cross-refs cover MAL/AniList/MangaUpdates/Kitsu only. `SourceMatchService` searches each source by normalized title; auto-accept needs the score, word coverage **and** shape (`ScrobbleMatching`: above `StandaloneThreshold` 0.85 a title stands alone, below it one title must be the other plus whole appended words; the bar never falls below the caller's own threshold, so the scrobbler at 0.93 never sees the relaxation). A **cross-id pass runs first** (`SourceExternalIds`): where a source publishes its own tracker links, an agreeing id accepts a result whatever its title scores, and a result whose shared ids *all* disagree is dropped before the title pass sees it; one agreement beats one disagreement. Only id forms MangaBaka stores are comparable, so uncomparable ids are dropped, not recorded (see `SourceExternalIds`). Lookups are capped at 3 per source (each is a rate-limited page fetch), and a failed lookup is swallowed per candidate, not per source.
- **A user-made result (`SourceSeriesResult.UserGenerated`, today only WEBTOON CANVAS) needs its credited author to agree before the title pass may take it** (`SourceMatchService.AuthorsAgree`: names split on `,`/`/`/`&`, words sorted, so `Fujimoto Tatsuki` equals `Tatsuki Fujimoto`). A series with no author on record therefore never auto-maps to CANVAS; the cross-id pass and a manual link still can. Catalogued results are decided by title alone.
- **The sources are searched in parallel, and everything after that is back in priority order** (`SourceMatchService.AutoMatchAsync`, `MaxParallelSources`). Three phases: one DB read of the existing mappings, then a `Task.WhenAll` fan-out that touches **no** `DbContext` and no `Series` entity (the searches get a `MatchTarget` snapshot; EF entities are not thread-safe), then a single-threaded apply loop sorted by priority. That ordering is load-bearing: the highest-ranked source has to win a cross-reference disagreement (`SourceExternalIds.Merge` order), `mapped` has to come out in priority order, and the `Add` has to re-check the DB because the snapshot is seconds old and `(SeriesId, SourceName)` is unique. Per-source failures are caught **inside** each task, or one would cancel the rest.
- **A Discover preview's source search is handed to the add that follows it** (`SourceMatchSearchCache`, keyed by MangaBaka id, one hour). `FindCandidatesAsync` stores every per-source outcome except the ones that threw; `AutoMatchAsync` takes the entry once and answers those sources from it, searching only the rest. Reuse requires the same `MatchTarget` (title, original title, cross-ids), and priority is re-read at add time rather than reused. Take-once is deliberate: a later re-match of a library series must search fresh.
- **The Discover first-chapter preview writes nothing** (`SeriesPreviewService`, `PreviewController`, `SeriesPreviewReader.tsx`): no series row, no progress, stats, XP or inbox, and the reader component is presentational only. Pages live under the `SeriesPreviewDir` cache, two jobs run per instance, finished jobs are kept an hour. **It does not wait for the whole source search:** `FindCandidatesAsync` writes each candidate to a channel as its source settles, each one is listed as it arrives, and the first listing with chapter 1 is fetched straight away, whatever its priority. A source whose listing starts later is only tried once every source has answered and none had chapter 1, then in priority order. The searches keep running under the job's token after the chapter is in, because the add that usually follows reuses them through `SourceMatchSearchCache`; only the listings stop. The content-rating ceiling is checked before any network work, and the ceiling check must match the list queries (a null rating is hidden there).
- **`SourceMatchState.NoMatch` is reported as soon as that source's search settles without an accepted result; a search that throws reports `Failed`.** The worker collects the `Failed` names (`FailureCollector`), sends them on `sourceMatchFinished` as `failedSources`, words the inbox row for them (`inbox.sourceMatch.failed`/`matchedSomeFailed`) and skips the "link one by hand" alert while any source went unasked, unless that source has failed its last `SourceFailureStreaks.Threshold` (3) searches in a row (in memory, reset on restart) and another source answered in this run, so a permanently broken source cannot hold the alert back forever. A failed Suwayomi search also runs the health check early (`HealthCheckJob.RequestSoonAsync`, at most once a minute). `Searching` is reported for every source before the fan-out. The pushes go through `EventBroadcaster.SourceMatchProgress` from `SourceMatchWorkerHostedService`'s `HubProgress`, deliberately **not** `Progress<T>`, which would let a `Matched` overtake its own `Searching`. The pushes are decoration: `sourceMatchFinished` still delivers the finished table.
- **A confirmed match's cross-references map the sources nothing matched** (`SourceMatchService.SeedFromCrossRefsAsync`): one `GetSeriesAsync` (proves the id resolves and gets the canonical URL) and the mapping is written, no search. `ExternalIdService.SourceSeriesIdServices` lists the services whose key **equals a source's `ISource.Name`**, so such a key can never be renamed independently of its source. Seeds come from **cross-id-confirmed matches only**, the pass runs **after** the search loop (a source's own result is canonical, and the loop's already-mapped check doesn't see unsaved rows), and on a conflict the higher-priority source's id wins. It never writes the id back to the `Series` columns: `SeriesIdentity.For` ranks `md:` above `al:`/`mal:`, so filling `MangaDexUuid` would move the series' stats history to a key nothing was written under.
- **Local MangaBaka DB** (`{ConfigDir}/mangabaka.db`, ~3GB, `MangaBakaLocalStore`). `total_chapters`/`final_volume`/`merged_with` are TEXT, may be fractional. `tags_v2` has per-tag weight + `is_spoiler` + 96% coverage vs 50% for plain `tags` — prefer it (`genres_v2` is empty though, use `genres`).
- **User tags ≠ `Series.Tags`.** The latter is provider metadata, replaced wholesale on every refresh. User tags are the `Tag` entity + `SeriesTags` join — query via `db.SeriesTags`, never `db.Series.SelectMany(s => s.UserTags)` (skip-nav `SelectMany` compiles to SQL APPLY, unsupported by SQLite, 500s at runtime not build time). `SavedFilter` spec JSON is case-insensitive on read; unknown fields silently degrade to defaults rather than throwing — never rename/reorder a field.
- **Spoiler tags stripped per series at ingest, not display.** The spoiler flag is per-*series*, not per tag name (same tag name is spoiler for some series, not others) so no global word list works. API fallback path never sees `tags_v2` and can't filter at all.
- **`Series.AltTitles` are `LocalizedTitle` (title + language code) in every language the dump has, and `Series.Title` stays canonical.** A display-language preference (`ui.titlelanguage`, per user) is resolved into `SeriesDto.DisplayTitle` at DTO-build time and **nowhere else**: `Title` and `SortTitle` name the folder on disk and every file in it, so a preference that rewrote them would rename one person's library to satisfy another's. Sorting therefore still follows the English title. The same titles fill ComicInfo's `LocalizedSeries` (alt title in the chapter's language, else `OriginalTitle`).
- **`Series.Incognito` is picked once, at add time** (`IncognitoRatingRules`, `library.incognitobyrating`): the add form's explicit mode always wins, and only an absent value consults the content-rating rules. Unset falls back to `{pornographic: Full}`, but a stored `{}` means "every rating off" and must survive the round trip, so the settings response spells out all four ratings. A metadata refresh never re-applies the rules.
- **Naming formats are evaluated when a name is *computed*, never retroactively** (`Maki.Core.Naming`, `library.seriesfolderformat` + `library.chapterformat`, read only through `NamingService`).
  - `Series.FolderName` is a stored fact: `FileNameBuilder.BuildRelativePath` takes it as given, or a format changed after a series was added would send downloads into a folder that doesn't exist. Changing a format moves nothing on disk; only `SeriesRenameService` (`POST series/{id}/rename`) does, and it refuses on an in-flight download or when two chapters resolve to one name.
  - There is no "drop this when empty" syntax: absent values render empty and a cleanup pass tidies whitespace and empty brackets, which is why the combo tokens `{Series TitleYear}` and `{Chapter VolChap}` carry their own punctuation. A token's *spelling* is load-bearing: the separator inside it replaces spaces in the value and an all-lower/all-upper token cases it, so `{Series.Title}` and `{SERIES TITLE}` are not variants of `{Series Title}`.
  - `.cbz` and the ` [xx]` language suffix (see `downloads.md`) are appended by the builder, never part of a format. The default chapter format must reproduce the pre-format names exactly; `FileNameBuilderTests` must keep passing unchanged.
  - **A file backing several chapters is named for the whole span** (`NamingContext.Through`/`WholeVolumes`): `Vol.1` when it holds every known chapter of its volumes, `Vol.1 Ch.1-3` for part of one, `Ch.1-6` with no volume info. `Vol.1 Ch.1-6` would parse back as plain chapter 1.
  - **`library.renameimportedfiles` is the one switch that turns naming off** (default on, gated inside `TorrentImportService.ApplyNamingAsync` so the unattended job and the reviewed import agree). It covers only files adopted from disk; an explicit `POST series/{id}/rename` still renames everything.
  - **Collision checks compare names case-insensitively on every host** (`SeriesRenameService.OccupiedNames`, never `File.Exists`).
- **Language preference re-ranks the source priority list, it does not filter it afterwards** (`SourceLanguagePreference`, `sources.languageorder` + `sources.languagesdisabled`). Each source lands in the bucket of the highest-ranked *enabled* language it declares in `ISource.SupportedLanguages` (compared with `LocalizedTitle.Matches`), buckets concatenate in language order, and `sources.priorityorder` breaks ties inside one. A source declaring none of the enabled languages is **skipped by auto-match entirely** (not searched, not seeded, no priority slot); it is still linkable by hand, and `SourceMappingController.PriorityForAsync` then ranks it after every ranked source. Unset means English alone. **This is a separate switch from `sources.disabled`**: nothing here touches `SourceAvailability`. Auto-created mappings on a `SupportsLanguageFilter` source get `LanguageFilter` seeded with the enabled languages that source publishes, in preference order (null when that is plain English); existing mappings are never rewritten, and MANGA Plus is deliberately not covered because a language there is a separate title id.
- **A globally disabled source (`sources.disabled`) never touches `SourceMapping.Enabled`**: it's a second independent switch, so re-enabling restores the prior per-series layout. Every site that picks usable mappings (sync, download resolve, queue, link, refresh, health checks, the mapping controller) must test `m.Enabled` and the disabled set together; missing one lets a disabled source still download or a broken series report healthy.
- **Adding a series doesn't wait for source matching**: `Series.SourceMatchPending` is a column so it survives a crash mid-match, and `SourceMatchWorkerHostedService` re-queues anything still flagged at startup. `SourceMatchQueue` has two match lanes; `Interactive` (an add, a single re-match) is always read before `Background` (library import, import lists, bulk re-match). A library import's series still owes a file link after its match (`PendingImportLink`, see `downloads.md`), so the match stage hands its inbox row to the link stage. `SeriesRequestsController.Approve` must keep `deferSourceMatching = false`.
- **`StatsEvent.SeriesKey` is the identity the log aggregates on, not `SeriesId`** (the FK is `SetNull` on delete). `SeriesIdentity.For` resolves `mb:` → `md:` → `al:` → `mal:` → `t:{normalized title}` at event time; only `SeriesIdentityService` (`AdoptOrphansAsync`, `RekeyAsync`) and `SeriesIdentityRepairService` rewrite a written key. **Its normalization is persisted, so changing it orphans every key already written.** `SeriesController.Delete` must snapshot the key *before* removing the row, or the removal event lands under a title key while the reads kept the provider key.
- **`SeriesIdentityService.AdoptOrphansAsync` runs on every series create** (`SeriesCreationService` + `LibraryImportService`), matching orphans on the new series' key **or** its title key, exact only, never fuzzy, and rewriting their `SeriesKey`. It also merges tombstoned `ReadingState` rows (both keys null) forward-only into any live row, which stops a re-add restarting the high-water mark. `ChapterProgress` cascades on delete and is unrecoverable; only the aggregate survives.
- **`SeriesIdentityRepairService` runs after `StatsBackfillService`, in two marker-gated passes**: `stats.identityRepairDone` keys pre-migration rows and adopts orphans (fills a severed `SeriesId` and a null key), and `stats.identityKeyRepairDone` realigns rows linked to a live series whose `SeriesKey` is older than the one the series now resolves to. No count, timestamp or user is touched.
