# Series identity, source matching, naming

Migrated out of the root CLAUDE.md so this only loads when touching source-matching/identity/naming code.

- **The image-cache rebuild is asymmetric on purpose** (`ImageCacheRebuildService`, `POST system/image-cache/rebuild`): reader thumbnails and source-preview samples are only ever *deleted* (any request regenerates them), while posters are *re-downloaded*, because nothing regenerates a poster on demand. `Series` stores only `CoverPath`, never the cover URL, so every poster costs a provider lookup — hence the default pass targets only covers that are missing or fail `Image.Identify` (a truncated download looks fine to `File.Exists`), and the forced one is behind a confirm. It runs as a durable, trigger-less Quartz job so a restart can interrupt it; the single-flight claim is taken inside the service, not the endpoint, so a trigger that never reaches a job can't leave the status stuck on "running".
- **`SeriesRequest` needs no permission to create** — it's the 403 fallback for users without `AddSeries`/`DownloadChapters`. Reading/resolving is admin-only except a requester sees/withdraws their own **pending** rows (not resolved ones — `ResolutionNote` is the answer they got). Display snapshot (title/cover/year) resolved server-side, never from the request body. Approval goes through `SeriesCreationService` (same code as `SeriesController.Add`, extracted so they can't drift), with `deferSourceMatching = false` since a chapter range gets queued right after.
- **MangaBaka has no MangaDex IDs** — cross-refs cover MAL/AniList/MangaUpdates/Kitsu only. `SourceMatchService` searches each source by normalized title (auto-accept needs the score, word coverage **and** shape: above 0.85 a title stands alone, between the caller's threshold and that it must be the other title plus whole appended words. A short generic title is a *fragment* of any longer title made of the same words and scores higher there than a real subtitle variant does — "High School Boy" hits 0.65 on "She's Adopted a High School Boy!" and 0.71 on "Magic, High School, and a Boy" while "Hajime no Ippo" only reaches 0.64 on "Hajime no Ippo: Fighting Spirit!" — so no threshold can split them and word coverage can't either, since it divides by the shorter title's word count. Extension is checked both ways and unbounded; "Naruto" extends to "Naruto Gaiden..." too and it's the 0.32 score that stops it. The bar is clamped to never fall below the caller's own threshold, so the scrobbler at 0.93 never sees the relaxation), but runs a **cross-id pass first** (`SourceExternalIds`): where a source publishes its own tracker links, an agreeing id accepts a result whatever its title scores, and a result whose shared ids *all* disagree is dropped before the title pass sees it. One agreement beats one disagreement — a stale link on one tracker is common, two works sharing a tracker id is not. Only id forms MangaBaka stores are comparable, so MangaUpdates' legacy numeric ids and Kitsu's slugs are **dropped, not recorded** (an uncomparable id can't produce a match but can produce a false mismatch that throws away the right result). The pass costs nothing for a series with no cross-ids, and lookups are capped at 3 per source — each is a page fetch through that source's shared rate limiter. A failed lookup is swallowed per candidate, not per source, or one bad page would skip a title pass that would have matched.
- **A confirmed match's cross-references map the sources nothing matched** (`SourceMatchService.SeedFromCrossRefsAsync`). MangaFire names the MangaDex title, Atsumaru's search index names the WeebCentral entry, so once one source is confirmed the neighbours' series ids are simply known: one `GetSeriesAsync` (proves the id still resolves, and is the only way to get the canonical URL) and the mapping is written, no search and no title involved. `ExternalIdService.SourceSeriesIdServices` lists the services whose key **equals a source's `ISource.Name`** — that name equality is how one resolves to the other, so such a key can never be renamed independently of its source. Seeds come from **cross-id-confirmed matches only** (a title match's cross-references are exactly as good as the guess that produced them), the pass runs **after** the search loop (a source's own result is canonical — WeebCentral's own ids carry the slug, the borrowed one is the bare ULID — and the loop's already-mapped check reads the DB, which doesn't see unsaved rows), and on a conflict the **higher-priority source's** id wins. It deliberately never writes the id back to the `Series` columns: `SeriesIdentity.For` ranks `md:` above `al:`/`mal:`, so filling `MangaDexUuid` on a series that had none would move its whole stats history to a key nothing was written under.
- **Local MangaBaka DB** (`{ConfigDir}/mangabaka.db`, ~3GB, `MangaBakaLocalStore`). `total_chapters`/`final_volume`/`merged_with` are TEXT, may be fractional. `tags_v2` has per-tag weight + `is_spoiler` + 96% coverage vs 50% for plain `tags` — prefer it (`genres_v2` is empty though, use `genres`).
- **User tags ≠ `Series.Tags`.** The latter is provider metadata, replaced wholesale on every refresh. User tags are the `Tag` entity + `SeriesTags` join — query via `db.SeriesTags`, never `db.Series.SelectMany(s => s.UserTags)` (skip-nav `SelectMany` compiles to SQL APPLY, unsupported by SQLite, 500s at runtime not build time). `SavedFilter` spec JSON is case-insensitive on read; unknown fields silently degrade to defaults rather than throwing — never rename/reorder a field.
- **Spoiler tags stripped per series at ingest, not display.** The spoiler flag is per-*series*, not per tag name (same tag name is spoiler for some series, not others) so no global word list works. API fallback path never sees `tags_v2` and can't filter at all.
- **`Series.Incognito` is picked once, at add time** (`IncognitoRatingRules`, `library.incognitobyrating`): the add form's dropdown sends an explicit mode and always wins, and only an absent value consults the content-rating rules, so an older client still gets them. Unset falls back to `{pornographic: Full}`, but a stored `{}` means "every rating off" and must survive the round trip — the settings response therefore spells out all four ratings. A metadata refresh never re-applies the rules; re-rating a title would silently undo a manual change.
- **Naming formats are evaluated when a name is *computed*, never retroactively** (`Maki.Core.Naming`, `library.seriesfolderformat` + `library.chapterformat`, read only through `NamingService`). `Series.FolderName` is a stored fact: `FileNameBuilder.BuildRelativePath` takes it as given rather than re-deriving it, or a format changed after a series was added would send downloads into a folder that doesn't exist. Changing a format moves nothing on disk — `SeriesRenameService` (`POST series/{id}/rename`) is the only thing that does, and it refuses on an in-flight download or when two chapters resolve to one name. There is no syntax for "drop this when empty": absent values render empty and a cleanup pass (collapse whitespace, trim joining punctuation, drop `()`/`[]` left holding nothing) tidies up, which is why the combo tokens `{Series TitleYear}` and `{Chapter VolChap}` carry their own punctuation. A token's *spelling* is load-bearing — the separator inside it replaces spaces in the value and an all-lower/all-upper token cases the value, so `{Series.Title}` and `{SERIES TITLE}` are not cosmetic variants of `{Series Title}`. `.cbz` is appended by the builder, never part of a format. The default chapter format reproduces the pre-format hardcoded names exactly; `FileNameBuilderTests` is the guard on that and must keep passing unchanged.
- **A globally disabled source (`sources.disabled`) never touches `SourceMapping.Enabled`** — it's a second independent switch so re-enabling restores the prior per-series layout. Eight call sites must test `m.Enabled && !disabled.Contains(m.SourceName)` together (sync, download, queue, link, refresh, health checks) — missing one lets a disabled source still download or a broken series report healthy.
- **Adding a series doesn't wait for source matching** — `Series.SourceMatchPending` column (not an in-memory set, so it survives a crash mid-match) tracks it; `SourceMatchWorkerHostedService` re-queues anything still flagged at startup. `SeriesRequestsController.Approve` must keep `deferSourceMatching = false` since it queues a chapter range immediately after.
- **`StatsEvent.SeriesKey` is the identity the log aggregates on, not `SeriesId`.** The FK is `SetNull` on delete, so a series removed and re-added used to split into an orphaned half (no cover, no link) and a live half starting at zero. `SeriesIdentity.For` resolves `mb:` → `md:` → `al:` → `mal:` → `t:{normalized title}`, written once at event time and never updated — **its normalization is persisted, so changing it orphans every key already written**. `SeriesController.Delete` must snapshot the key *before* removing the row or the removal event lands under a title key while the reads kept the provider key.
- **`SeriesIdentityService.AdoptOrphansAsync` runs on every series create** (`SeriesCreationService` + `LibraryImportService`), matching orphans on the new series' key **or** its title key — exact only, never fuzzy: a wrong split is visible and reportable, a wrong merge silently corrupts both series with no undo. It also merges tombstoned `ReadingState` rows (both keys null) forward-only into any live row, which is what stops a re-add restarting the high-water mark. `ChapterProgress` cascades on delete and is genuinely unrecoverable — only the aggregate survives.
- **`SeriesIdentityRepairService` is marker-gated (`stats.identityRepairDone`) and runs after `StatsBackfillService`** — keys pre-migration rows, then adopts. It only ever fills in a severed `SeriesId` and a null key; no count, timestamp or user is touched.
