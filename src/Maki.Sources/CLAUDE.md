# CLAUDE.md — Maki.Sources

Non-obvious per-source scraper facts (`ISource` implementations). Migrated out of the root CLAUDE.md so they only load when working here.

- **MangaDex delists English chapters of licensed titles.** For E2E tests use unlicensed titles (e.g. Hajime no Ippo) — licensed ones (Frieren) have 0 downloadable EN chapters.
- **MangaFire requires FlareSolverr**; FlareSolverr-fetched JSON comes back `<pre>`-wrapped (unwrapped in `MangaFireSource`).
- **MangaPlus is protobuf now — never send `format=json`.** That parameter used to hand back JSON; the edge 403s any request carrying it (nginx, not the API), which is why every call failed. Responses are decoded by `PbMessage`, a wire-format reader written to avoid a Google.Protobuf dependency plus generated code for an unpublished schema; the field numbers are named constants at the top of `MangaPlusSource`. Test fixtures are recorded binary bodies, so `FakeHttpClientFactory` takes a second, binary map.
- **MangaPlus needs a residential IP** (datacenter IPs get banned) and a `SESSION-TOKEN` header. Any value works (the site generates a UUID client-side and keeps it in localStorage), so one random per-process value is enough; without it the API answers **200** with an "Account Banned" error popup rather than a 4xx. Only first-few/latest-few chapters per title are free. Pages are XOR-encrypted with a per-page key on `PageRequest.XorKeyHex`.
- **TCB Scans / MangaPlus / Flame Comics have no search endpoint** — all three match against a cached full catalog (`SourceCatalog`), filtered by normalized title. Empty catalog is treated as stale so a failed fetch doesn't pin "no results" for the whole TTL. TCB's domain rotates on DMCA takedowns.
- **Flame Comics is read through its Next.js `__NEXT_DATA__` blob**, not markup. Missing blob **throws** rather than returning empty (a Cloudflare interstitial shouldn't read as "no chapters" and silently stall a monitored series). `/browse` also lists prose novels (`novel_id` not `series_id`) — filter on `series_id`. A chapter's `images` object is keyed by page index **as a string** — sort numerically or page 10 lands between 1 and 2.
- **Webtoons chapter numbers are `episode_no`**, not the "Ep. N" in the title (restarts every season, collides on identity). CANVAS titles print no episode number at all. Episode lists page 10 at a time, no bulk endpoint (653-episode series = 73 requests). Some Originals cap the public list to ~9 episodes without the app. `webtoon-phinf.pstatic.net` hotlink-blocks every Referer but its own — only proxy through `SearchController`'s `/search/cover`.
- **Asura is manhwa/manhua**, JSON API, no descrambling needed (site's tile-scramble isn't applied to the API's `page.url`). Premium chapters with 0 pages are skipped.
- **ImageSharp pinned to 3.1.12** (Split License) — 4.x needs a paid build-time license key. Don't upgrade it.
- **Page fetching**: `GetPagesAsync` returns `PageRequest`s carrying their own `Headers` end-to-end; resolve pages at **download** time, not enqueue time (MangaDex at-home URLs are short-lived).
- **Four sources publish cross-site tracker ids** (`ISource.GetExternalIdsAsync`, consumed by `SourceMatchService`): **MangaDex** in `attributes.links` on the search response itself, so it fills `SourceSeriesResult.ExternalIds` instead and costs nothing; **Atsumaru** on `manga/page` (`mangaBakaId`/`malId`/`anilistId`/`kitsuId`/`mangaUpdatesId` — MangaBaka's own id among them, the key our metadata is stored under, and some arrive as bare numbers rather than strings); **WeebCentral** as anchors on the series page (AniList + MangaUpdates, no MAL); **MangaFire** as `a.tracker-link` in `.title-detail__trackers` (MAL + AniList + MangaUpdates + MangaDex, the widest set) — those links are rendered into the DOM and are **not** in the detail JSON, so `MangaFireBrowser.ExternalLinksAsync` reads the page rather than capturing an API response. Atsumaru's search index carries `weebCentralId` and none of the tracker ids, while its series page carries the trackers and not that — both halves are kept (`SourceExternalIds.Merge`), since `weebCentralId` is a **WeebCentral mapping**, not evidence about identity, and it rides the existing search request via `include_fields`. MangaPill publishes none. Everything else is unchecked and inherits the default (no ids, no code).
- **MangaKakalot (`mangakakalot.gg`) is entirely behind Cloudflare** — every HTML page 403s a plain client — so it takes `IHtmlFetcher` (the one-method seam on `ChallengeAwareFetcher`: direct with cached clearance first, FlareSolverr on a miss) rather than an `IHttpClientFactory`. That interface exists so the parser can be tested against recorded fixtures; the concrete fetcher drags in FlareSolverr and app settings. **The chapter list is not in the series HTML at all** — the page ships an empty `#chapter-list-container` and fills it from JS — so it comes from `/api/manga/{slug}/chapters`, which pages **50 at a time** unless asked for more and must be walked by `offset` until `has_more` is false (Tower of God is 658). `/home/search/json?searchword=` looks like a better search than scraping `/search/story/{keyword}`, and is deliberately **not** used: it only answers JSON to a request carrying `X-Requested-With: XMLHttpRequest` **and** a form-urlencoded `Content-Type`, Cloudflare lets it through only sometimes, and neither condition survives the FlareSolverr fallback — which would hand back HTML where JSON was parsed. Covers and page images share TopManhua's `2xstorage.com` CDN, which **403s a request with no `Referer`** (hence the `CoverHosts` entry, so the cover proxy supplies one, and the `Referer` on every `PageRequest`). Search-result thumbnails carry an unterminated `alt` attribute that swallows the attributes after it; `src` comes first and survives.
- **MangaKatana 404s a search that matches nothing** instead of serving an empty result page, so `SearchAsync` checks the status itself rather than using `GetStringAsync` — otherwise every unmatched title threw out of auto-match and 500'd `/api/v1/search/source`. The search parameter is `search_by=book_name` (`m_name` is not a value the site accepts), and a search matching exactly **one** title redirects to that series page, where there is no `div#book_list` to read — the single hit is built from the detail markup at `response.RequestMessage.RequestUri` instead.
- **Adding a source**: one `ISource` impl in `Maki.Sources` + one `AddSingleton<ISource, ...>()` registration. Return chapters via `SourceChapterList.Normalize` (dedupes by `(Number, Volume, Language)`).
