# Custom sources (Custom/)

- **Custom sources are definitions, not code** (`Custom/`, plan in `docs/custom-sources-plan.md`). `CustomSourceProvider` builds one `CustomSource` per entry in `sources.custom`, named `custom-{id}`; the id never changes, because it is what mappings, priority and `ChapterFile.SourceName` store. Entries are kept verbatim (`CustomSourceStore`), so one this build can't read survives a save of another, and it still registers as an `InvalidCustomSource` whose every call throws `SourceErrorException`: a source that vanished from the registry would have its mappings skipped silently. Only `CustomSourceService` (Api) writes, then reloads the registry and calls `SourceChapterListCache.EvictSource`. **`chapters.url` is required**: downloads, the scout and upgrade scans call `GetPagesAsync` with a chapter rebuilt from `SourceSeriesId`/`SourceChapterId` alone (no `Url`), so the page URL must come back from the two ids; the test run checks it against every listed row's own link. An `id` regex runs against the link's resolved path, not the raw attribute. A list extractor that matches nothing on a page that fetched fine throws `SourceErrorException` (not a bare `InvalidOperationException`, which `DownloadFailureReason` files as `unexpected` and `SourceFailover` never counts). Every request of one source, HTML and page images alike, waits on its own `SpacingGate` (`CustomSourceThrottle`, keyed by source name, interval updated in place on an edit, no timers); page images go out through the `PageRequest.Fetch` hatch for that reason, since the `pages` client has no per-source limit. `HtmlFetchRequest.Headers` reach only the direct request; FlareSolverr takes no custom headers. Regex extractors run the backtracking engine with a 250 ms timeout, and a timeout becomes a `SourceErrorException`. Not `NonBacktracking`: on .NET 10.0.1 it misses matches of any pattern that starts with an optional character (`x?/img/p/...` found 1 of 40), and `CustomSourceTests` pins that. Regex matches are un-escaped (`\/`, `\u0026`, HTML entities), because script payloads like Next.js's `self.__next_f` carry URLs escaped. `"engine"` (`madara`, `mangathemesia`, `keyoapp`, `heancms`) replaces the four sections with a `CustomSource.{Engine}.cs` partial (Madara over `Common/MadaraParser`, moved out of `Toonily/`). HeanCMS reads its JSON API on `api.{host}`, the one other host `FetchAsync` allows, which the validator holds to the site's host or a subdomain. A repository-installed definition keeps `origin` after a local edit and sets `detached`; only a save with `fromRepository` writes `origin`, `previous` and `detached` as given, and a hand edit always takes them from the stored entry; the validator refuses an engine definition that still carries sections, and `SeriesTemplate`/`ChapterTemplate` (not `Definition.Series.Url`) are what every caller uses, since an engine implies them. The wizard's guessers live in `Custom/Inference/` and only ever propose a section: everything they produce must pass the validator and run through the same engine (`CustomSourceGuessTests` checks both against the built-in sources' fixtures). `chapters.group` fills `SourceChapter.Group` (so `{Chapter Group}` and ScanInformation); `chapters.locked` is a flag (`CustomExtractor.Matches`: the css descendant exists, an `attr` is present and not false/0, or a `regex` matches) that sets `SourceChapter.Locked` and makes the source declare `ListsLockedChapters`; a literal or empty `locked` is refused, and the test run fails a locked sample chapter. Engines ignore both and keep their page-time `ChapterLockedException`. Lanternleaf (fixtures `premiumtoon-*`) covers them. SilentQuill (fixtures `silentquill-*`) is the reference case: chapter links are root-relative slugs, pages live only in the RSC payload, and images 403 without a browser User-Agent.
