# Suwayomi sources (Suwayomi/)

- **Suwayomi sources are not registered, they are supplied** (`Suwayomi/`, plan in `docs/suwayomi-source-plan.md`). `SuwayomiSourceProvider` builds one `SuwayomiSource` per entry in `suwayomi.sources`, named `suwayomi-{mihonSourceId}`, from that stored snapshot alone, so the registry is the same whether Suwayomi is up or not; anything that writes `suwayomi.*` must call `SourceRegistry.ReloadAsync`. **The snapshot holds every installed source, not a chosen few** (refreshed by `SuwayomiController` on connection save and when Manage sources opens), so `SourceAvailability.DefaultsOn` is false for every Suwayomi source and they all start off; anything that treats "registered" as "chosen" (the thumbnail relay, the language ranking's offered list) has to check the enabled state instead. **Ids are the portable ones**: `SourceSeriesId`/`SourceChapterId` are the manga's and chapter's source-relative `url` (what Mihon restores backups by), never Suwayomi's local int ids, which are looked up per instance and cached in `SuwayomiMangaIdCache` keyed by base URL. A cached id can outlive a recreated Suwayomi database and name another manga, so every refresh compares the url that comes back and re-resolves on a mismatch, and `fetchChapterPages` is asked for its chapter's url for the same reason. A manga the instance has never seen cannot be looked up (there is no resolve-by-url call) and throws a `SourceErrorException` telling the admin to search it once in Suwayomi; never recover by title search. **Under a login mode an unauthenticated GraphQL call answers 200 with `Unauthorized` in `errors[]`**, not 401 (matched as the whole message or the part after graphql-java's `Exception while fetching data (...) :` prefix, so an extension's site error that merely contains the word does not trigger a token renewal); `SuwayomiAuthHandler` buffers only GraphQL POST bodies to see that, never page GETs (stall timeout). `aboutServer` needs no credentials under `ui_login`, so `SuwayomiConnectionTester` sends it with `SkipAuth` before signing in: otherwise the auth handler logs in first, and a server older than v2.2 (no login mutation) fails the login instead of saying it is too old. **A wrong password is not "Unauthorized"**: Suwayomi's `login` throws `Incorrect username or password.`, which arrives as a plain GraphQL error, so `SuwayomiTokenStore` turns any login error except a missing `login` field into a 401 and answers the same connection's next logins from memory for 30 seconds; a changed password is tried at once. A site's own 404 and 429 come through as `HTTP error 404`/`429` in the error text and are mapped to a 404 `HttpRequestException` (so a download fails over at once) and `RateLimitException`. Token state lives in the singleton `SuwayomiTokenStore`, not the handler, because handler chains rotate; it is minted for one `SuwayomiConnection` value, so a changed URL or password drops it on the next request. **Page and thumbnail paths come back hardcoded `/api/v1/...` without `server.webUISubpath`**, so `SuwayomiConnection.Resolve` appends them to the base path rather than resolving them as relative URLs. Chapter numbers arrive as a widened 32-bit float (10.1 is `10.100000381469727`) and are narrowed back before use; `-1` means unknown. Mixed-language sources (`all`/`multi`/`other`) are registered but `NeedsSetup` until the admin picks one chapter language in Manage sources: `SourceAvailability` keeps them disabled whatever the settings say and `ListChaptersAsync` throws, never defaulting to `en`. v2.1 lacks `fetchMangaAndChapters` and `contentWarning`; `SuwayomiClient` falls back on the validation error and remembers it, rather than parsing versions. The fallback's `fetchChapters` names no manga, so a chapters-only refresh also reads `manga(id)` from Suwayomi's database, or the stale-id check would have nothing to compare on v2.1. The health probe's source list skips the API client's concurrency limit (`RateLimitingHandler.Skip`) so a busy sync can't time it out into a false alert. `SuwayomiMangaIdCache` empties a map past 20,000 entries; every entry is one cheap lookup away. Every `fetchSourceManga` upserts its results into Suwayomi's database as non-library rows, which is what Suwayomi's own browse does. Tests route the fake server by `operationName` (`Suwayomi/SuwayomiHarness.cs`), since every GraphQL call is the same URL.
